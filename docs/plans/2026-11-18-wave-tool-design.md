# 웨이브 시스템과 웨이브 세팅 도구 설계

> 상태: **설계 제안**. 요구(구성과 주기를 쉽게 세팅, 빠른 테스트, 버전으로 관리하고 비교)는 ansirh가 정했고, 아래 구조는 제안이다.
> 작성: sub-1 세션, 2026-11-18 밤. 기준 코드: main `e5bfbf9` 시점의 `Stage/WaveSpawner.cs`, `Data/MobDefinition.cs`, `Stage/StageStart.cs`.
> 코드를 읽고 설계한 것이고 실행해 본 것이 아니다.

## 1. 지금 상태

- 웨이브 설정이 **씬 안의 `WaveSpawner` 컴포넌트**에 들어 있다. 값을 바꾸려면 씬을 열어야 하고, 씬 생성 도구를 다시 돌리면 사라진다. 버전을 나눠 둘 방법이 없다.
- 주기와 수가 **곡선 두 개**(Interval, Count)다. "이 구간에서 몇 초마다 몇 마리"를 숫자로 읽고 쓰기 어렵다.
- 잡몹 종류가 **하나만** 들어간다(`Mob` 칸 하나). 근접과 원거리를 섞을 수 없다.
- 아티스트 맵 방식(Stage Start 표식)으로 만든 씬에는 **웨이브가 아예 없다.**
- 유지할 규칙(결정 #34): 웨이브는 끝없이 나온다. 끝 지점으로 갈수록 거세진다. 멈춰 있어도 계속 나오지만 주기가 짧아지지는 않는다(가장 멀리 간 진행도를 따른다).

## 2. 구조

### 2.1 웨이브 설정을 에셋 하나로: `WavePlan`

한 스테이지의 웨이브 설정 전체를 데이터 에셋(ScriptableObject) 하나에 담는다. **에셋 하나가 버전 하나다.**

```
WavePlan (에셋)
 ├ 메모         : 이 버전에서 무엇을 바꿨는지 한 줄
 ├ 첫 웨이브까지 : 3초
 ├ 구간 목록     : 진행도에 따라 바뀌는 웨이브 내용 (아래 표)
 ├ 돌발 목록     : 특정 진행도에 처음 닿을 때 한 번 나오는 무리 (선택)
 └ 등장 위치 규칙 : 분대에서 떨어진 거리, 앞쪽 비율, 무리 크기
```

**구간 목록** — 표 한 줄이 구간 하나다. 진행도(0 = 시작 지점, 1 = 끝 지점)가 그 줄의 "시작" 이상이면 그 줄을 쓴다.

| 시작(진행도) | 주기(초) | 구성 |
| --- | --- | --- |
| 0.0 | 12 | 근접 8 |
| 0.3 | 9 | 근접 12, 원거리 2 |
| 0.6 | 7 | 근접 18, 원거리 4 |
| 0.85 | 5 | 근접 26, 원거리 6 |

- 구성은 "잡몹 종류 + 마리 수"의 목록이다. 종류를 몇 개든 섞을 수 있다.
- 구간 사이를 부드럽게 잇는 옵션(보간)을 둔다. 끄면 계단식으로 바뀐다. 기본은 끔(표에 적은 숫자가 그대로 나오는 쪽이 읽기 쉽다).
- 곡선 대신 표를 쓰는 이유: "V자 구간부터 웨이브가 늘어난다" 같은 기획 문장을 줄 하나로 옮길 수 있고, 두 버전을 나란히 놓고 숫자로 비교할 수 있다.

**돌발 목록** (선택) — 진행도 X에 **처음 닿는 순간 한 번** 나오는 무리. 예: 진행도 0.5에서 근접 40. 주기와 무관하다. 3스테이지의 "마지막에 몰려온다" 같은 연출용이다.

**등장 위치 규칙** — 지금 `WaveSpawner`에 있는 값 그대로: 분대에서의 최소·최대 거리(14~22), 끝 지점 쪽에서 오는 비율(0.7), 무리 크기(8)와 퍼짐(1.5).

### 2.2 스포너는 에셋을 읽기만 한다

- `WaveSpawner`는 `WavePlan` 칸 하나를 갖고, 주기와 구성을 거기서 읽는다. 진행도 계산과 등장 위치 고르기는 지금 코드를 그대로 쓴다.
- 매 웨이브마다 에셋을 다시 읽는다. **플레이 중에 에셋 값을 바꾸면 다음 웨이브부터 적용된다.**
- 스테이지가 쓰는 버전은 한 곳에서 정한다: 생성된 스테이지 씬은 `WaveSpawner`의 칸, 아티스트 맵 씬은 **Stage Start 표식의 Wave Plan 칸**. 칸이 비어 있으면 웨이브가 없다.
  - 이것으로 "아티스트 맵 씬에 웨이브가 없다"가 같이 해결된다.
- 미니 보스는 이 에셋에 넣지 않는다. 미니 보스는 지금처럼 맵 위의 표식(`MiniBossSpawn`)으로 놓는다. 위치가 중요한 것은 맵에, 숫자인 것은 에셋에 둔다.

### 2.3 버전 관리

- 폴더: `Assets/Data/Waves/<스테이지>/`. 파일 이름: `Stage1_v01.asset`, `Stage1_v02.asset` …
- 새 버전 = 기존 에셋을 복제(Ctrl+D)하고 숫자를 올린 뒤 메모를 적는다. 도구 창의 버튼으로도 할 수 있다(§3).
- 지난 버전을 지우지 않는다. 파일이 남아 있으므로 언제든 다시 꽂아 비교할 수 있고, git에도 버전별로 남는다.
- 어느 버전이 "지금 쓰는 것"인지는 스테이지의 칸이 가리키는 에셋으로 정해진다.

## 3. 웨이브 도구 창

메뉴 `BoneSquadKiting/Wave Tool`. 에디터 창 하나에서 세팅, 전환, 비교를 한다.

**왼쪽: 버전 목록** — 스테이지를 고르면 그 폴더의 버전들이 나온다. 지금 쓰는 버전에 표시.

- **이 버전으로 플레이**: 스테이지의 칸을 이 에셋으로 바꾼다. 플레이 중이면 다음 웨이브부터 적용된다.
- **복제해서 새 버전**: 번호를 올린 사본을 만들고 그것을 연다.

**가운데: 편집** — 선택한 버전의 구간 표, 돌발 목록, 등장 규칙을 표 형태로 고친다. (에셋을 직접 선택해 인스펙터에서 고쳐도 같다.)

**오른쪽: 요약과 비교** — 숫자를 계산해서 보여 준다. 두 버전을 골라 나란히 볼 수 있다.

| 항목 | 뜻 |
| --- | --- |
| 구간별 분당 마리 수 | 구성 합계 ÷ 주기 × 60 |
| 구간별 분당 체력 합 | 위 값 × 잡몹 체력. 분대 화력과 비교하는 기준 |
| 최대 동시 수 도달 예상 | 처치가 없다고 가정했을 때 상한(지금 200)에 닿는 시간 |

비교할 때는 달라진 칸에 색을 넣는다.

**테스트를 빠르게 하는 기능**

| 기능 | 설명 |
| --- | --- |
| 진행도 지정 시작 | 진행도 X 지점에서 분대를 시작시킨다. 후반 구간만 바로 볼 수 있다 |
| 지금 웨이브 한 번 | 버튼을 누르면 현재 구간의 웨이브가 즉시 한 번 나온다 |
| 웨이브 멈춤/재개 | 주기를 세우고 다시 돌린다 |
| 무적 | 유닛이 죽지 않는다. 웨이브의 양만 보고 싶을 때 |
| 배속 | 게임 속도 0.5× / 1× / 2× |

**플레이 중 표시** — F1 정보창에 한 줄: 버전 이름, 진행도, 현재 구간, 다음 웨이브까지 남은 시간, 살아 있는 잡몹 수, 누적 등장·처치 수.

## 4. 플레이 기록 (재미 검증용, 선택)

버전을 비교하려면 숫자뿐 아니라 "실제로 해 보니 어땠나"가 필요하다. 한 판이 끝날 때(클리어·전멸·플레이 중지) 한 줄을 기록한다.

| 기록 | |
| --- | --- |
| 시각, 스테이지, 웨이브 버전 | |
| 결과 | 클리어 / 전멸 / 중단 |
| 걸린 시간, 도달한 최대 진행도 | |
| 등장 수, 처치 수, 최대 동시 수 | |
| 유닛 사망 수, 부활 수, 종료 시 생존 수 | |

- 저장 위치: 프로젝트 폴더의 `PlayLogs/waves.csv`(Assets 밖, git에 올리지 않음). 도구 창에서 버전별 평균을 표로 본다.
- 에디터에서만 기록한다. 빌드에는 넣지 않는다.
- 숫자로 재미를 판정하지는 않는다. "v03은 평균 2분에 전멸, v04는 4분에 클리어" 정도의 비교 근거다.
