# 비주얼 교체 구조 설계: 모델, 투사체, 이펙트

> 상태: **설계 제안**. "교체하기 쉽게 만든다"는 요구는 ansirh가 정했고(결정 #43), 아래 구조는 제안이다.
> 작성: sub-1 세션, 2026-11-18. 기준 코드: main `970fcdc` 시점의 `SquadView`, `MobView`, `ShotView`, `BossView`, `TelegraphView`, `JuiceFx`.
> 코드를 읽고 설계한 것이고 실행해 본 것이 아니다.

## 1. 지금 상태

게임 로직과 화면 표시는 이미 분리되어 있다. 유닛·잡몹·투사체는 좌표만 가진 데이터이고, `...View` 스크립트가 매 프레임 그 좌표를 읽어 오브젝트를 옮긴다. 그래서 교체 작업은 **View가 무엇을 만들어 내는가**만 바꾸면 된다. 로직은 건드리지 않는다.

교체를 막는 것은 네 가지다.

| 문제 | 위치 |
| --- | --- |
| 임시 도형을 코드가 직접 만든다(`CreatePrimitive`) | `SquadView`, `MobView`, `ShotView` |
| 크기와 높이를 코드가 정한다(`UnitScale`, 고정 높이) | 같은 곳 |
| 피격 표시가 "렌더러 하나의 발광색"을 바꾸는 방식이다. 파츠가 여러 개인 모델에서는 일부만 번쩍인다 | `SquadView` |
| 이펙트가 파티클 하나, 링 하나로 고정되어 있다 | `JuiceFx` |

그리고 스테이지가 5개 씬이라, 씬마다 인스펙터 칸에 따로 넣는 방식이면 **같은 교체를 다섯 번** 해야 한다.

## 2. 구조

### 2.1 아트 세트 에셋 하나에 모은다

`ArtSet`이라는 데이터 에셋(ScriptableObject) 하나에 공용 비주얼을 전부 모은다. 모든 씬의 View가 같은 에셋을 가리킨다. **프리팹을 한 번 바꿔 넣으면 5개 스테이지에 모두 적용된다.**

| 칸 | 내용 |
| --- | --- |
| Unit Prefab | 일반 유닛 |
| Leader Prefab | 분대장(비우면 Unit Prefab) |
| Shot Prefab | 투사체 |
| Muzzle Fx | 발사 순간, 유닛 위치 |
| Shot Hit Fx | 투사체 명중 지점 |
| Unit Hit Fx | 유닛 피격 |
| Unit Death Fx | 유닛 사망 |
| Revive Loop Fx | 살리는 동안 살리는 유닛에 붙어 반복 |
| Revive Done Fx | 부활 완료 순간, 살아난 지점 |
| Telegraph Material | 장판 예고 |
| Pattern Blast Fx | 장판이 터지는 순간, 장판 중심 |
| End Point Closed / Open Fx | 끝 지점의 닫힘·열림 표시 |

종류마다 다른 것은 각자의 정의 에셋에 둔다.

| 에셋 | 칸 |
| --- | --- |
| `MobDefinition` | Prefab, Death Fx |
| 미니 보스 정의 | Prefab, Intro Fx, Death Fx (스테이지 설정 설계 §3.3) |
| 보스 | Prefab, Phase Two Fx, Death Fx |

### 2.2 비어 있으면 지금의 임시 도형

**모든 칸은 비워 둘 수 있다.** 비어 있으면 지금처럼 임시 도형을 쓰거나 이펙트를 건너뛴다. 그래서 아트가 준비되는 대로 하나씩 채워 넣을 수 있고, 덜 채운 상태에서도 게임이 돌아간다. 마감 직전에 일부만 교체된 채로 빌드해도 깨지지 않는다.

### 2.3 코드와 프리팹의 약속

코드가 하는 일을 최소로 줄이고 나머지는 프리팹 안에서 아티스트가 정한다.

**코드가 하는 것**

- 프리팹 인스턴스의 **루트 위치**를 옮긴다(높이 0, 발밑 기준).
- 루트의 **방향**을 돌린다: 이동 중이면 이동 방향, 사격 중이면 대상 방향.
- 켜고 끈다(살아 있음/죽음), 재사용한다(풀링).

**코드가 하지 않는 것**

- 크기를 바꾸지 않는다. 크기는 프리팹 안에서 맞춘다.
- 머티리얼을 건드리지 않는다.

**프리팹을 만드는 규칙**

| 규칙 | 이유 |
| --- | --- |
| 루트는 빈 오브젝트, 모델은 그 자식 | 크기·높이·회전 보정을 자식에서 하고 루트는 코드가 움직인다 |
| 발밑이 루트의 원점(높이 0) | 코드가 루트를 지면 높이에 둔다 |
| 앞이 +Z | 코드가 루트를 진행 방향으로 돌린다 |
| 콜라이더를 붙이지 않는다 | 게임은 콜라이더 없이 거리로 판정한다. 붙어 있으면 이동 가능 범위 계산과 클릭에 걸릴 수 있다 |

게임 안의 크기 기준(모델을 이 크기에 맞춘다):

| 대상 | 반경 | 비고 |
| --- | --- | --- |
| 유닛 | 0.25 | 유닛 간격이 0.5 안팎이라 폭이 그보다 넓으면 서로 파묻힌다 |
| 잡몹 | 0.3 | |
| 미니 보스 | 0.8 | 초기값 |
| 보스 | 1.15 | 투사체 명중 반경과 같다 |

### 2.4 상태 전달: 애니메이션은 선택

모델에 애니메이션이 있으면 재생하고, 없으면 그냥 미끄러지듯 움직인다. 프리팹 루트에 `Animator`가 있고 아래 이름의 파라미터가 있으면 코드가 값을 넣는다. **없는 파라미터는 무시한다.**

| 파라미터 | 종류 | 언제 |
| --- | --- | --- |
| `Moving` | bool | 이동 중 |
| `Attack` | trigger | 사격한 순간 |
| `Hit` | trigger | 피격 |
| `Reviving` | bool | 살리는 중 |
| `Die` | trigger | 사망 |

- 사망: `Die`를 보낸 뒤 정해진 시간(프리팹 쪽 값, 기본 0)이 지나면 끈다. 0이면 지금처럼 즉시 사라지고 Death Fx만 남는다.
- 피격 번쩍임: 지금의 발광색 방식은 임시 도형에만 쓴다. 프리팹을 쓰는 경우에는 `Hit` 트리거와 Unit Hit Fx로 대신한다.
- 이 부분을 `UnitVisual` 같은 작은 컴포넌트 하나에 모아 두면 유닛·잡몹·미니 보스·보스가 같은 코드를 쓴다.

### 2.5 이펙트: 사건이 일어난 자리에 프리팹 생성

이펙트는 전부 "어떤 일이 일어났다 → 그 자리에 프리팹을 하나 만든다"로 통일한다. 이펙트의 내용(파티클, 빛, 소리)은 프리팹 안에서 아티스트가 만든다.

- 생성한 이펙트는 스스로 끝나고 사라져야 한다. 파티클 시스템의 Stop Action을 Destroy로 두거나, 코드가 프리팹에 적힌 수명 뒤에 지운다. 둘 다 없으면 3초 뒤에 지운다.
- Revive Loop Fx처럼 붙어서 반복하는 것은 상태가 끝날 때 코드가 지운다.
- 화면 흔들림과 화면 번쩍임은 프리팹이 아니라 수치다. 지금처럼 `JuiceFx`에 둔다.
- 사건 목록은 `GameDirector`의 이벤트로 이미 일부 나와 있다(`PatternStarted`, `PatternResolved`, `PhaseTwoStarted`, `ReviveCompleted`). 유닛 피격·사망, 투사체 발사·명중, 잡몹 사망이 추가로 필요하다.

### 2.6 투사체

- Shot Prefab을 재사용(풀링)한다. 방향은 날아가는 방향으로 돌린다.
- 꼬리(Trail Renderer)가 있으면 **재사용할 때 꼬리를 지워야 한다.** 안 지우면 이전 위치에서 새 위치로 선이 그어진다. 코드가 꺼낼 때 처리한다.
- 유도 투사체라 방향이 매 프레임 바뀐다.

## 3. 성능 주의

잡몹이 최대 200마리, 유닛 25명이다. 임시 도형에서는 문제가 없었지만 모델로 바꾸면 달라진다. **아래는 일반적인 기준이고 이 프로젝트에서 측정한 값이 아니다. 교체 후 실제 프레임을 재야 한다.**

- 가장 무거운 것은 뼈대 애니메이션이 있는 모델 200개다. 잡몹은 폴리곤 수를 낮게, 머티리얼 하나, 뼈 수를 적게 잡는다.
- 잡몹은 실시간 그림자를 끄는 것을 먼저 고려한다.
- 이펙트는 한 번에 많이 터진다(잡몹이 한꺼번에 죽을 때, 미니 보스 사망 시 전멸 연출). 이펙트 하나의 파티클 수를 작게 잡는다.
- 프레임이 떨어지면 먼저 줄일 것: 잡몹 그림자 → 잡몹 애니메이션 → 동시 최대 수.

## 4. 작업 순서 제안

아티스트가 붙여 볼 수 있게 되는 순서로 잡았다.

1. **프리팹 칸 + 아트 세트 에셋 + 비어 있으면 임시 도형** (유닛, 투사체, 잡몹, 보스). 방향 돌리기 포함. 여기까지 되면 아티스트가 모델을 넣어 볼 수 있다.
2. **이펙트 칸**: 사건 → 프리팹 생성.
3. **애니메이션 파라미터.**
4. 분대장, 미니 보스, 부활, 끝 지점은 각 기능이 구현될 때 같은 방식으로 칸을 만든다.

1번이 들어가면 아티스트용 안내(프리팹 만드는 법, 어디에 넣는지)를 따로 쓴다.
