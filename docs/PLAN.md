# 기획

> 결정이 바뀌면 `docs/decisions.md`와 이 문서의 해당 장을 같은 커밋에서 고친다.

## 1. 개요

- **한 줄 설명:** 25명의 원거리 딜러를 하나의 덩어리처럼 조작해, 보스의 장판 패턴을 **진형 전환**으로 회피하며 녹이는 쿼터뷰 액션. 스테이지 6개: 몰려오는 적 떼와 에픽 몬스터를 뚫고 끝 지점까지 가는 진행 스테이지 5개 + 보스 스테이지 1개(결정 #21).
- **원본:** HTML 프로토타입 `KITE SQUAD 25` (단일 index.html, canvas 2.5D).
- **엔진:** Unity 6000.3.28f1 · URP · 쿼터뷰 원근 카메라(결정 #18). 카메라 이동은 화면 가장자리 스크롤(결정 #20).
- **아트:** M1은 임시 기하도형. 이후 아티스트 아트로 교체.

## 2. 문제

- 원딜 1명 조작은 흔하다. **25명을 한 덩어리로 지휘**하며, 보스 장판을 "진형 모양"으로 회피하는 손맛을 검증한다.

## 3. 해결

- 분대 중심점(FormationCenter) 1개를 **우클릭 스마트 커맨드**(지면→이동, 적→그 적 공격)와 **어택땅(A+좌클릭)** 으로 지휘 → 유닛은 `중심 + 진형오프셋` 추종, 사거리 내 적 자동 평타. 단 **유닛은 멈춘 상태에서만 공격한다**(결정 #15): 기준은 유닛 개별이고, 이동 명령·어택땅·진형 전환으로 자리를 옮기는 동안에는 사격하지 않는다. 사거리가 닿지 않는 유닛은 개별로 접근하지 않고 서 있으며, 플레이어가 진형 변경이나 진형 회전으로 해결한다.
- **진형 전환**(결정 #19): Q/W/E/R(밀집·일자·원형·십자).
- **카메라**(결정 #20): 분대를 자동으로 따라가지 않는다. 마우스 커서를 화면 가장자리에 대면 그 방향으로 이동한다.
- **진형 회전**(결정 #16): 마우스 휠로 분대 중심을 축으로 진형을 돌린다. 휠 아래 = 시계 방향, 휠 위 = 반시계 방향. 회전 중인 유닛은 사격하지 않는다.
- **분대 사거리**(결정 #17): 유닛 개별 사거리와 별도로 진형 원점 기준 사거리를 둔다. 어택땅 분대는 적이 분대 사거리 안에 들어오면 멈추고, 우클릭으로 적을 지정한 분대는 그 적이 분대 사거리 안에 들어오면 멈춘다.
- 보스가 4종 장판(core/gate/quadrant/shell)을 예고 → 대응 진형(원형/일자/십자/밀집)으로 피해 인원 최소화.
- 유닛이 죽을수록 DPS 영구 감소 → 회피 숙련이 곧 화력.

## 4. 기능 (마일스톤)

- **M1 — 프로토타입 이식 + 조작/데이터 확장 (현재 목표):** 아레나·쿼터뷰 카메라, 분대 이동/진형 4종·**진형 회전(마우스 휠)**, 자동 평타 + **어택땅(A+좌클릭)·우클릭 타겟 공격**(적 레지스트리·오더 상태머신), 보스(HP 24000)·4패턴·2페이즈, **패턴·진형은 ScriptableObject 데이터 에셋**(결정 #8), HUD(보스바/생존/DPS/진형패널/경고), 승패·일시정지·재시작, 임시 기하도형. 수치는 프로토타입과 동일. 상세: `docs/plans/2026-11-18-m1-kite-squad-port.md`.
- **M2 — 잡몹 떼:** 최대 ~200 잡몹. 직선추적+공간해시 분리. 아군↔적 충돌(적이 밀려남, Rigidbody 없이 거리기반 푸시). 오더별 타겟 우선순위·예약 피해·유도 투사체(결정 #13 제안), 클릭 판정 교체(결정 #14). 설계 초안: `docs/plans/2026-11-18-m2-mob-swarm-design.md`.
- **M3 — 진행 스테이지 1개:** 장애물 없는 통로형 직선 맵, 스테이지별 경계, 시작·끝 지점, 진행 거리 기반 스폰과 추격 떼, 스테이지 흐름(클리어·실패·재시도).
- **M4 — 에픽 몬스터:** 보스 패턴 시스템을 범용 시전기로 일반화(결정 #22 제안), 움직이는 에픽, 다중 장판, 에픽 HUD.
- **M5 — 6스테이지 완성:** 스테이지 2~5 데이터, 에픽 종류, 스테이지 연결(1→6), 난이도 조정.
- **M6 — 아트·마감:** 아티스트 아트 교체, 사운드, 화면 문구, 빌드.
- **이후(시간이 남으면):** 장애물·굽은 맵(NavMesh 데이터, Flow Field, 벽 눌림 보정), 스테이지 간 분대 인계·강화, 대시(SPACE).

M2 이후의 순서는 결정 #23(제안됨)이다. 스테이지와 에픽의 기획 초안: `docs/plans/2026-11-18-stage-structure-design.md`.

## 5. 구조

- 게임플레이 좌표는 프로토타입과 동일한 (x, z) 월드를 Unity **XZ 평면**에 직접 매핑. 높이 `h`→Y. 투영 수식 대신 Unity 카메라 사용(원근, 결정 #18).
- 주요 모듈: GameDirector(상태머신) · FormationController(중심+진형+**오더**) · SquadUnit(추종·평타) · ShotSystem(투사체·**타겟 획득**) · Boss/BossAttackSystem(패턴) · **EnemyRegistry/IEnemy·IDamageable**(적 추상화, M1=보스1) · DangerShape/FormationSlots 평가기 · Input(스마트 커맨드·어택땅) · HUD(uGUI).
- 패턴·진형은 **데이터(ScriptableObject)** 로 분리: `PatternDefinition`(예고시간·추천진형·조언·DangerShape), `FormationDefinition`(슬롯 생성 규칙), `AttackSequence`(패턴 묶음). 코드는 범용 평가기만 — 패턴/진형 추가는 에셋 추가로.
- 상세 파일 구조는 M1 플랜 문서 참고.
