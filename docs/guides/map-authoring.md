# 맵 제작 안내: 이동 가능 범위 설정 (아티스트용)

> 대상: 스테이지 맵을 만드는 아티스트.
> 기준 코드: `bone-squad-kiting/Assets/Scripts/Stage/WalkGridBaker.cs`, `WalkOutline.cs`, `StageSetup.cs`.
> 최종 갱신: 2026-11-18.

## 한눈에 보기

분대가 갈 수 있는 곳과 적이 찾아오는 길은 **이동 가능 범위** 하나로 정해진다. 아티스트가 정하는 방법은 세 가지이고 함께 쓴다.

| 하고 싶은 것 | 방법 |
| --- | --- |
| 걸을 수 있는 바닥을 만든다 | 터레인의 레이어를 **Ground**로 |
| 플레이 영역의 모양을 정한다 | **외곽선**을 그린다 (Include) |
| 영역 안의 일부를 못 가게 한다 | 오브젝트에 **Obstacle** 레이어, 또는 **외곽선**으로 구멍을 낸다 (Exclude) |

어떤 칸이 이동 가능이 되려면 세 조건을 모두 만족해야 한다.

1. Include 외곽선 안쪽이다 (Include 외곽선이 하나도 없으면 이 조건은 없다).
2. Exclude 외곽선 바깥이다.
3. 바닥(Ground)이 있고, 근처에 장애물(Obstacle)이 없다.

베이크 버튼은 없다. 맵을 고치면 다음 플레이에 바로 반영된다.

## 처음 한 번: 씬 준비

1. 빈 오브젝트를 만들어 `WalkGridBaker` 컴포넌트를 붙이고 **맵 중앙**에 둔다.
2. **Size**(x, z)가 플레이 영역 전체를 덮게 한다. 오브젝트를 선택하면 Scene 뷰에 흰 테두리 상자로 보인다. **상자 밖은 전부 이동 불가**다.
3. **Ground Mask** = Ground, **Obstacle Mask** = Obstacle로 지정한다.
4. 나머지 값(Cell Size 0.75, Clearance 0.3)은 그대로 둔다. 바꿔야 할 것 같으면 프로그래머에게 먼저 말한다.

## 1단계: 바닥 (터레인)

- 터레인 오브젝트의 레이어를 **Ground**(7번)로 바꾼다. 터레인에는 콜라이더가 이미 붙어 있다.
- **플레이 영역은 높이 0 근처로 대체로 평평하게** 만든다. 약간 울퉁불퉁한 것은 괜찮다(결정 #31). 다만 유닛과 적은 지면을 따라 오르내리지 않고 **높이 0의 평면 위에서 평평하게** 움직인다. 솟은 곳에서는 발이 묻히고 꺼진 곳에서는 떠 보이므로, 굴곡은 유닛 발목 높이 안쪽으로 작게 둔다.
- 플레이 영역 **바깥**은 자유롭게 조형해도 된다. 절벽, 산, 구덩이로 분위기를 만든다.
- 터레인은 큰 사각형 한 장이라, 여기까지만 하면 **터레인 전체가 이동 가능**이다. 모양은 2단계의 외곽선으로 잡는다.

터레인이 아닌 바닥 오브젝트를 쓴다면 콜라이더(`MeshCollider` 또는 `BoxCollider`)를 붙이고 레이어를 Ground로 한다.

## 2단계: 외곽선으로 영역 그리기

점을 찍어 닫힌 도형을 만들고, 그 안쪽을 이동 가능(또는 불가)으로 지정하는 방법이다.

### 만드는 법

1. 빈 오브젝트를 만들고 `WalkOutline` 컴포넌트를 붙인다. 이름은 알아보기 쉽게 짓는다(예: `Outline_PlayArea`).
2. 그 오브젝트의 **자식**으로 빈 오브젝트를 여러 개 만든다. 자식 하나가 꼭짓점 하나다.
3. 자식들을 Scene 뷰에서 옮겨 영역의 모서리에 놓는다.
4. `WalkOutline`의 **Mode**를 고른다.
   - **Include**: 이 도형 안쪽만 이동 가능하다. 플레이 영역의 모양을 정할 때 쓴다.
   - **Exclude**: 이 도형 안쪽은 이동 불가다. 영역 안에 구멍을 낼 때 쓴다(호수, 낭떠러지, 건물 자리).

### 규칙

- **점의 순서는 Hierarchy 창의 자식 순서다.** 위에서 아래로 차례대로 선이 이어지고, 마지막 점에서 첫 점으로 자동으로 닫힌다. 도형이 꼬여 보이면 Hierarchy에서 자식 순서를 바꾼다.
- **선이 서로 교차하면 안 된다.** 8자 모양이 되지 않게, 도형을 따라 한 바퀴 도는 순서로 둔다. 시계 방향이든 반시계 방향이든 상관없고 오목한 모양도 된다.
- **점은 3개 이상이어야 한다.** 2개 이하면 도형으로 치지 않고 무시한다.
- 점의 **높이(y)는 상관없다.** 위에서 내려다본 위치(x, z)만 쓴다.
- 꺼 둔(비활성) 자식은 점에서 빠진다. 점을 잠시 빼 보고 싶을 때 쓸 수 있다.
- Include 외곽선은 **여러 개 그려도 된다.** 그중 하나라도 안쪽이면 이동 가능이다. 떨어진 두 구역을 따로 그릴 수 있지만, 두 구역이 이어지려면 도형이 서로 겹쳐야 한다.
- Exclude는 Include보다 우선한다. 겹치는 곳은 이동 불가다.
- 곡선은 점을 촘촘히 찍어 만든다. 다만 판정은 0.75 크기의 칸 단위라 그보다 세밀하게 찍어도 결과는 같고, 비스듬한 경계는 최대 반 칸 정도 계단 모양으로 나온다.
- 외곽선은 같은 씬에 있기만 하면 자동으로 적용된다. `WalkGridBaker`에 따로 등록할 것이 없다.

### Scene 뷰에서 보이는 모습

| 색 | 뜻 |
| --- | --- |
| 초록 선과 점 | Include 외곽선 |
| 빨강 선과 점 | Exclude 외곽선 |
| 회색 | 점이 3개 미만이라 아직 도형이 아님(무시됨) |

외곽선은 오브젝트를 선택하지 않아도 항상 보인다.

## 3단계: 오브젝트로 길 막기

벽, 바위, 나무 기둥, 건물처럼 눈에 보이는 장애물은 오브젝트로 막는다.

- 콜라이더를 붙이고 레이어를 **Obstacle**(8번)로 바꾼다.
- 콜라이더가 **바닥에 닿아 있어야** 막힌다. 게임은 바닥 근처만 검사하므로 공중에 떠 있는 것(나뭇가지, 아치 윗부분)은 막지 않는다.
- 지나갈 수 있는 장식(풀, 작은 돌, 바닥 무늬)은 레이어를 바꾸지 않는다(Default 그대로).
- **터레인에 페인팅한 나무와 풀은 길을 막지 못한다.** 페인팅한 나무는 터레인의 일부로 취급되어 오히려 바닥으로 잡힌다. 나무로 길을 막으려면 그 자리에 Exclude 외곽선을 그리거나, 나무를 프리팹으로 따로 배치하고 Obstacle 레이어를 준다. (이 항목은 Unity 동작에 대한 이해로 적은 것이고 이 프로젝트에서 확인하지는 않았다. 페인팅한 나무를 쓴다면 초록·빨강 칸으로 꼭 확인한다.)
- 보이지 않게 막고 싶으면 빈 오브젝트에 `BoxCollider`만 붙이고 Obstacle 레이어로 한다. 다만 이 용도는 Exclude 외곽선이 더 편하다.

## 4단계: 시작 지점과 끝 지점

1. 빈 오브젝트에 `StageSetup` 컴포넌트를 붙인다. `WalkGridBaker`와 같은 오브젝트에 붙여도 된다.
2. `StageSetup`의 칸을 채운다.
   - **Ground** = 이 씬의 `WalkGridBaker`
   - **Squad** = 분대 오브젝트(`FormationController`)
   - **Cam** = Main Camera(`EdgeScrollCamera`). 넣으면 카메라가 맵 범위 밖으로 나가지 않는다
3. **시작 지점:** 빈 오브젝트를 원하는 위치에 두고 `StageSetup`의 **Start Point**에 끌어다 넣는다. 분대 중심이 그 위치에서 시작한다.
4. **끝 지점:** 빈 오브젝트를 두고 **End Point**에 넣는다. **End Radius**(기본 3)가 도착 판정 반경이다. 분대 중심이 그 원 안에 들어오면 도착이다.

알아둘 것:

- 높이(y)는 상관없다.
- 시작 지점을 이동 불가 칸 위에 두면 가장 가까운 이동 가능 지점으로 옮겨진다. 의도한 위치에서 시작하게 하려면 초록 칸 위에 둔다.
- 분대는 시작 지점을 중심으로 진형을 펼친다. 시작 지점 주변에 진형이 들어갈 공간(반경 4 이상)을 둔다.
- 끝 지점은 이동 가능한 곳에 두고, End Radius 원이 초록 칸과 겹치게 한다.
- 스테이지는 **모든 적을 쓰러뜨린 뒤 끝 지점에 도착하면** 클리어다. 끝 지점은 길의 마지막에 둔다.

Scene 뷰에서 보이는 모습(선택하지 않아도 보인다):

| 표시 | 뜻 |
| --- | --- |
| 초록 구 + 세로선 | 시작 지점 |
| 파란 원 + 세로선 | 끝 지점. 원의 크기가 End Radius |

## 분대가 경계에서 움직이는 방식

맵을 만들 때 알아두면 좋은 동작이다.

- 분대 중심은 이동 가능 범위 밖으로 나가지 못한다. 범위 밖을 클릭하면 가장 가까운 이동 가능 지점으로 간다.
- 진형의 일부가 범위 밖에 걸리면 그 유닛들은 중심 쪽으로 당겨져 벽 앞에 선다. 진형이 벽에 눌려 찌그러진다.
- **분대는 벽을 돌아가는 길을 스스로 찾지 않는다.** 벽 건너편을 클릭하면 벽 앞에서 멈춘다. 플레이어가 꺾이는 곳마다 클릭해야 하므로, 길이 심하게 꼬이면 조작이 번거로워진다.
- 적은 길을 찾아서 돌아온다.

## 외곽선과 오브젝트 중 무엇을 쓸까

| 상황 | 권장 |
| --- | --- |
| 플레이 영역 전체의 모양 | Include 외곽선 |
| 호수, 낭떠러지처럼 넓고 모양이 불규칙한 못 가는 곳 | Exclude 외곽선 |
| 벽, 바위, 건물처럼 눈에 보이는 물체 | Obstacle 레이어 |
| 지형 모델이 아직 없는데 길부터 잡고 싶을 때 | Include 외곽선 |

## 결과 확인하기

`WalkGridBaker` 오브젝트를 선택하면 Scene 뷰에 칸이 그려진다.

- **초록 칸** = 이동 가능
- **빨강 칸** = 이동 불가

플레이를 누르지 않아도 보인다. 외곽선 점을 옮긴 뒤 `WalkGridBaker`를 선택해 수시로 확인한다.

## 치수 기준

| 항목 | 값 | 설명 |
| --- | --- | --- |
| 칸 크기 | 0.75 | 이보다 얇은 벽이나 틈은 칸에 걸리지 않을 수 있다 |
| 통로 최소 폭 | 1.5 (2칸) | 1칸짜리 통로는 적이 대각선으로 지나가지 못해 막힌다 |
| 분대가 지나가는 통로 권장 폭 | 8 이상 | 원형 진형 지름(약 7.4)에서 계산한 값이고 플레이로 확인한 것은 아니다. 좁으면 일자 진형으로만 지나갈 수 있다 |
| 벽 두께 | 0.75 이상 | 얇으면 칸 사이로 빠져 구멍이 생길 수 있다 |
| 참고: 보스 아레나 | 24.6 × 20.4 | 전투가 벌어지는 넓은 공간의 기준 |

## 자주 나는 실수

| 증상 | 원인 |
| --- | --- |
| 전부 빨강이다 | 터레인 레이어가 Ground가 아니거나, `WalkGridBaker`의 Ground Mask가 비어 있거나, Include 외곽선이 엉뚱한 곳에 있다 |
| 외곽선을 그렸는데 아무 변화가 없다 | 점이 3개 미만이다(회색으로 보임). 또는 점이 `WalkOutline` 오브젝트의 자식이 아니다 |
| 외곽선 모양이 꼬였다 | Hierarchy의 자식 순서가 도형을 따라 도는 순서가 아니다. 선이 교차하면 결과가 엉뚱해진다 |
| 나무를 심었는데 그 자리가 초록이다 | 터레인에 페인팅한 나무다. Exclude 외곽선이나 Obstacle 오브젝트로 막는다 |
| 영역 일부가 통째로 빨강이다 | `WalkGridBaker`의 Size가 그 부분을 덮지 못한다 |
| 벽이 있는데 초록이다 | 벽에 콜라이더가 없거나, 레이어가 Obstacle이 아니거나, 콜라이더가 바닥에서 떠 있다 |
| 통로가 군데군데 빨강으로 끊긴다 | 통로가 너무 좁다. 장애물에서 0.3 안쪽 칸은 막힌 것으로 본다 |
| 장식을 놓았더니 길이 막혔다 | 장식의 레이어가 Obstacle로 되어 있다 |
| 유닛이 땅에 묻히거나 떠 있다 | 플레이 영역의 터레인 굴곡이 크다. 유닛은 높이 0 평면에서만 움직인다 |

## 맵을 넘길 때 확인할 것

- [ ] 시작 지점에서 끝 지점까지 초록 칸이 끊기지 않고 이어진다
- [ ] 초록이면 안 되는 곳(벽 안쪽, 영역 바깥)에 초록이 없다
- [ ] 분대가 지나가야 하는 길의 폭이 의도한 대로다
- [ ] 플레이 영역의 터레인이 높이 0 근처이고 굴곡이 작다
- [ ] 회색 외곽선(점 3개 미만)이 남아 있지 않다
